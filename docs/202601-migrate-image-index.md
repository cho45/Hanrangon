# 画像インデックスの移行手順 (2026年1月)

画像類似度検索のアルゴリズム変更（pHash -> dHash）およびインデックス構造の最適化（16bit BLOB -> 8bit INTEGER）に伴い、既存の画像インデックスを再構築する必要があります。

## 変更内容
- **アルゴリズム:** Perception Hash (pHash) から **Difference Hash (dHash)** に変更。構図やレイアウトの類似性に対してより直感に近い結果が得られます。
- **インデックス粒度:** 64bitハッシュを 16bit×4分割 から **8bit×8分割** に細分化。ハミング距離 7 までの「確実に似ている画像」を確実に見つけられるようになります。
- **DB構造:** `ngram.word` カラムを `BLOB` から `INTEGER` に変更し、検索速度の向上とDBサイズの削減を行いました。

## 移行手順

本作業により `images.db` が初期化されますが、画像レコードとインデックスのみが対象であり、エントリ本体（`data.db`）には影響しません。

### 1. アプリケーションの停止 (推奨)
データベースファイルを直接削除するため、安全のためにアプリケーションを停止します。

```bash
# 例: systemd を使用している場合
sudo systemctl stop hanrangon
```

### 2. 既存の画像データベースの削除
新しいスキーマを適用するため、既存の `images.db` を削除（または退避）します。

```bash
# 作業ディレクトリにて
mv var/db/images.db var/db/images.db.bak
```

### 3. アプリケーションの起動
アプリケーションを再起動します。起動時に `db/schema/images.sql` に基づいて新しい空のデータベースが自動的に作成されます。

```bash
sudo systemctl start hanrangon
```

### 4. 全画像の再インデックス実行
サブコマンドを使用して、全エントリから画像を抽出し、新しいロジックでハッシュ計算とインデックス作成を行います。

```bash
# --force フラグを付けて実行
./hanrangon index-images --force
```

※ 画像枚数が多い場合、並列処理（3並列）で実行されますが、完了まで数分〜数十分かかる場合があります。

## 検証方法
1. 管理画面の「画像一覧」にアクセスします。
2. 画像の右上に表示される 🔍 アイコンをクリックします。
3. 類似画像が「一致スコア（0〜8）」の降順で表示されることを確認します。
    - 全く同じ画像はスコア 8 で表示されます。
    - スコアが高いほど、納得感のある類似画像が表示されるはずです。

## トラブルシューティング
- **コマンドが見つからない:** `make build` を実行して最新のバイナリを生成してください。
- **インデックスが空のまま:** ジョブ一覧画面で `IndexImages` ジョブが失敗していないか確認してください。
