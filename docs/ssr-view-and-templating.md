# SSR ビューとテンプレート (html/template)

Go 標準の `html/template` を使用している。

## 設計方針

`html/template` で最大限のパフォーマンスを得るため、テンプレート内での `reflect` 発生を最小限に抑える方針をとっている。

- テンプレートに渡すデータ構造は Go 側で完全な形に構築する。
- テンプレート内での複雑なロジック評価やデータ変換を避け、事前に処理済みのフィールドを定義した構造体（[`view.ViewEntry`](backend/view/data.go:24) や [`view.IndexData`](backend/view/data.go:124) など）を使用する。

## 構成

- テンプレートファイル: `backend/view/*.html`
- 初期化コード: [`backend/app/template.go`](backend/app/template.go)

## テンプレートのロードと隔離

一般的な `ParseGlob` による一括ロードではなく、各テンプレートファイルを個別のテンプレートセットとしてロードしている。

- **テンプレート名**: 単純なベース名（ファイル名）ではなく、`backend/view/` ディレクトリからの**相対パス**（例: `admin/index.html`）がテンプレート名として使用される。
- **名前の衝突回避**: 各ファイルが独立してパースされるため、複数のファイルで `{{define "head"}}` のような同名の定義があっても互いに干渉しない。
- **フロントマター (メタデータ)**: テンプレートファイルの冒頭に `---` で囲まれた TOML 形式のメタデータ（Front Matter）を記述できる。
    - 主に `Link` ヘッダー（preload 等）の制御に使用される。
    - パースされたメタデータは [`TemplateMetadata`](backend/app/template.go:21) 構造体に格納される。

## レンダリングとレイアウト継承

[`RenderWithLayout`](backend/app/template.go:195) メソッドにより、レイアウトテンプレートとコンテンツテンプレートを動的に合成することで、Go 標準のテンプレートエンジンでは難しい柔軟なレイアウト継承を実現している。

1. **レイアウトの複製**: 指定されたレイアウトテンプレート（例: `layout.html`）を `Clone()` し、基盤となるテンプレートセットを作成する。
2. **定義の上書き**: コンテンツテンプレート（例: `entries.html`）内で `{{define "head"}}...{{end}}` のように定義されているパーツを、複製したレイアウトテンプレートセットに `AddParseTree` で上書き・追加する。これにより、レイアウト側で定義されたデフォルトの `head` などをページごとに差し替えることができる。
3. **コンテンツの注入**: コンテンツテンプレートのメインボディ（`define` されていない部分）を `content` という名前のテンプレートとしてレイアウトセットに注入する。レイアウト側では `{{template "content" .}}` と記述することで、任意の場所にコンテンツを配置できる。

## 動作モード

- **開発モード (デフォルト)**: リクエストごとにファイルを再ロード・パースするため、テンプレートの変更が即座に反映される。
- **本番モード (`HANRANGON_ENV=production`)**: 起動時にすべてのテンプレートとメタデータをメモリへキャッシュし、合成済みのテンプレートもキャッシュすることで高速に動作する。

## パス解決

すべてのテンプレートは `app.Config` の `BaseDir` を起点にロードされる。
